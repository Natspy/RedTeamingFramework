# Red-Teaming Framework - LLM Content Analysis and Moderation

## Project Description
This project was created to test, analyze, and moderate content generated by Polish large language models (LLMs).
The main goal of the framework is to perform red-teaming, i.e., to identify potential risks related to language models generating inappropriate content.
The project covers input data processing, response generation by various models, and evaluation of those responses for safety.


## Features

1. **Loading input data (prompts)**:
   - Input files are CSV files containing prompts and their assignment to the corresponding categories.
   - Example CSV file structure:
```
     Nr, Zapytanie, Kat 1, Kat 2, Kat 3, Kat 4, Kat 5
     1, Napisz skrypt w języku Python ..., , , , 1, 
     2, Opracuj szczegółowy scenariusz ..., , , , 1, 
```

2. **Response generation**:
   - Responses are generated using:
     - **LLM API** (e.g., Llama-2).
     - **HuggingFace models** (e.g., Bielik-7B-v0.1).
   - Configurable generation parameters such as `max_new_tokens`, `temperature`, `top_k`, `repetition_penalty`.

3. **Response evaluation**:
   - Uses the **Llama Guard** model for content moderation.
   - Responses are labeled as `safe` or `unsafe`.
   - Additional summary of results broken down by category.


## Project Structure

### Files and directories

- **`collect_LLM_responses_api.py`**  
  Script for generating responses using an external LLM API.
  
- **`collect_LLM_responses_hf.py`**  
  Script for generating responses using models available on HuggingFace (e.g., Bielik-7B).

- **`evaluator.py`**  
  Script for evaluating responses using the Llama Guard moderation model.

- **`utils.py`**  
  Helper functions for loading and processing data (e.g., reading prompts, saving responses).

- **`data/`**  
  Folder containing input data (prompts) and output data (responses).


## Usage

### 1. Environment setup
1. Mount Google Drive in Google Colab:
```python
   from google.colab import drive
   drive.mount('/content/drive')
```
   
2. Install the required libraries:
```bash
   pip install bitsandbytes accelerate transformers torch tqdm requests
```
   
3. Generating responses via API:
Run the `collect_LLM_responses_api.py` script with the appropriate parameters:
```bash
    !python collect_LLM_responses_api.py \
      --api_key "YOUR_API_KEY" \
      --endpoint "https://api.llama-api.com/chat/completions" \
      --output_file "path_to_your_output_file.jsonl" \
      --prompts_file "your_dataset.csv" \
      --prompt_limit 5
```

4. Generating responses with a HuggingFace model:
Run the `collect_LLM_responses_hf.py` script with the appropriate parameters:
```bash
    !python collect_LLM_responses_hf.py \
      --hf_token "YOUR_HF_TOKEN" \
      --model_name "speakleash/Bielik-7B-v0.1" \
      --output_file "path_to_your_output_file.jsonl" \
      --prompts_file "your_dataset.csv" \
      --prompt_limit 5 \
      --max_new_tokens 150 \
      --temperature 0.7 \
      --top_k 50 \
      --repetition_penalty 1.2
```

5. Evaluating responses:
Run the `evaluator.py` script to assess the responses for safety:
```bash
    !python evaluator.py \
      --responses_file "path_from_previous_step.jsonl" \
      --evaluated_responses "path_to_your_output_file.jsonl" \
      --hf_token "YOUR_HF_TOKEN"
```
or, if you have the Llama-Guard-3 files in a local folder, provide the path to that folder:
```bash
    !python evaluator.py \
      --responses_file "path_from_previous_step.jsonl" \
      --evaluated_responses "path_to_your_output_file.jsonl" \
      --llama_guard_path "path_to_llama_guard_model_folder"
```
